# 📡 32. Prometheus - collecting metrcis from web server

We can now observe host metrics in Grafana. Since we have a web server running in our hosts, it will be a good idea to also watching its metrics. Our application is using Nginx as the frontend web server and it has feature to collect statistical data. In this tutorial, we are going to do the task in the following 3 steps:

1. Enable Nginx collecting statistical data.
2. Run a Nginx exporter to read these data.
3. Update Prometheus for adding this exporter.

Nginx supports collecting data while running, to enable this, we just need update the config file. Our web application is running in docker container, so we can attach to the frontend container by command:

```
docker exec -it <frontedn container ID> sh
```
The Nginx config file is at location **/etc/nginx/conf.d/default.conf**, with content:

```
server {
    listen 80;

    # Serve frontend static files
    root /usr/share/nginx/html;
    index index.html;
    location / {
        try_files $uri /index.html;
    }

    # Reverse proxy for API calls
    location /api/ {
        proxy_pass http://backend.mylearningapp.local:8000/;  # backend is container name in Docker network
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        # Strip /api prefix before forwarding
        rewrite ^/api/(.*)$ /$1 break;
    }
}
```

Update it to add the 'stub_status':

```
server {
    listen 80;

    # Serve frontend static files
    root /usr/share/nginx/html;
    index index.html;
    location / {
        try_files $uri /index.html;
    }

    # Reverse proxy for API calls
    location /api/ {
        proxy_pass http://backend.mylearningapp.local:8000/;  # backend is container name in Docker network
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        # Strip /api prefix before forwarding
        rewrite ^/api/(.*)$ /$1 break;
    }

    location /nginx_status {
        stub_status on;
    }
}
```

Now reload the web server:

```
nginx -s reload
```

The above configuration file has added an endpoint 'nginx_status' for the web server, we can test it by command:

```
curl http://localhost/nginx_status
```

We'll see output like this:

```
Active connections: 1 
server accepts handled requests
 10 10 20
Reading: 0 Writing: 1 Waiting: 0
```

Pleae note, we should update our source code **/frontend/nginx.conf** and compile new image for frontend so the above update will be persisted.

Now we quit the docker container. In the host shell, run the command:

```
curl http://<host IP>/nginx_status
```

This is to make sure we can get the data outside docker container. For Prometheus, it can not read this data directly since the data is not in Prometheus data format. Like the Node Exporter which collect metrics from host, we need to run another exporter for colleting data from Nginx server. There is a docker application for it, we can run it by command:

```
docker run --rm -p 9113:9113 \
        --name nginx-exporter \
        --network monitor-net \
        nginx/nginx-prometheus-exporter:latest \
        --nginx.scrape-uri http://<host IP>/nginx_status
```
This docker application will read data from the above Nginx endpoint. It runs in the same docker network as Prometheus and Granfana containers we setup in previous tutorials. It opens port 9113 so we can config Prometheus to scrape data from this port.

After this Nginx exporter container is running, we need to make sure if it can get data from the web server endpoint. This container is running in docker network 'monitor-net' but it turns out it does not have any shell process available, there is no way to attach to it. We can run another docker in the same network to have a check:

```
docker run --rm -it --network monitor-net nicolaka/netshoot bash
```

This docker images contains various network related command so we can use it to prove if container in this newtork can access to Nginx web server endpiont.

We run command in this container:

```
nc -vz <host IP> 80
```

This command would fail. If we check host iptable rules:

```
iptables -vL INPUT --line-numbers -n -t filter
```

We could see the counter for the last rule, which rejects packets keeps increasing when we run the test command in container. This means our packet is blocked by iptable rules. We can add a rule to allow this access. First, check the IP address within the container which is running in docker network 'monitor-net'. Then on host, if we run command **ip addr**, we would see which network interface is for that docker network. For example, the command **ip addr** in  my host has the following output:

```
...
4: br-efc59ae80bb8: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP group default
    link/ether b2:4e:6d:20:3e:30 brd ff:ff:ff:ff:ff:ff
    inet 172.19.0.1/16 brd 172.19.255.255 scope global br-efc59ae80bb8
       valid_lft forever preferred_lft forever
    inet6 fe80::b04e:6dff:fe20:3e30/64 scope link
       valid_lft forever preferred_lft forever

...
```
Because the container in docker network 'monitor-net' in is subnetwork 172.19.0.0, so we know the corresponding network interface is **br-efc59ae80bb8**. Now we could add the iptable rule:

```
iptables -I INPUT 4 -i br-efc59ae80bb8 -p tcp --dport 80 -j ACCEPT
```

Try the nc command again, it can access port 80 now. So we can be sure the Nginx exporter can read data from Nginx server endpoint.

Besides, the Nginx exporter itself expose port 9113 for Prometheus to scrape data, so we need to update **prometheus.yml** to add a target for this new exporter. We can add a new job in the config file:

```
  - job_name: 'nginx'
    metrics_path: /metrics
    static_configs:
      - targets:
        - '<host IP>:9113'
```

The path '/metrics' is the default path that the Nginx exporter used to send metrics data.

Again, we would expect to meet the same issue of accessing host port 9113. We add a rule similar to the above rule:

```
iptables -I INPUT 4 -i br-efc59ae80bb8 -p tcp --dport 9113 -j ACCEPT
```

To make sure Prometheus has retrieved web server matrics, we can go to the Prometheus web console:

```
http://<Host1 IP address>:9090/query
```

Enter a metric named **nginx_connections_active** and execute it, we would see its output.

When this is done, we can continue to repeat the above steps in another host which is running web server, then add that target in prometheus.yml so Prometheus can scape web server metrics from these two hosts. Then we can add panels in Grafana to monitor these metrics.

Note, for the Nginx exporter running in the second host, since we need to access it from our first host, which traffic will go to Oracle Cloud netowrk, so we should add a security ingress rule in Oracle Cloud console just like we did in previous console.
