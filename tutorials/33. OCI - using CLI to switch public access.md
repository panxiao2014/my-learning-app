# 🔒33. OCI - using CLI to switch public access

Through the previous tutorials we have enabled the following public access to the running instances:

- Web access from port 80.
- Prometheus web console access from  port 9090.
- Grafana web access from port 3000.

These are only for personal use and I don't want to expose them to the whole public network. One way is to update security list to only allow access from my local laptop. But since the IP address provided by ISP to our home devices is not static it is hard to implement this method. I am going to use another method: I'll update the security list, to put the rules for the above access permission into a new list. We can add this list to the subnet where the instances are running. If we want to disable the access we can simply remove the security list from the subnet.

Since this might be done frequently it is better to do it with a script so we don't need to log in to the web console and navigate to the subnet page every time. Below is very brief tutorial of using OCI CLI for this purpose.

I am following the [Oracle CLI guide](https://docs.oracle.com/en/learn/exadb-cc-oci-cli-intro/index.html#task-1-install-oci-cli) to install and config the command tool in my local laptop. There is one issue occurred: there are two ways to generate RSA key pair for the secure connection during CLI tool setup, one is to generate from local and upload the public key to web console, the other way is to generate the key from web console and download the private key to local. The first method didn't work for me and I chose to use the second method to successfully complete the setup.

Try to run the following command to check if OCI CLI has setup correclty:

```
oci os ns get
```

First we get the ID of the VCN where our instances are running:

```
oci network vcn list --compartment-id <compartment id>
```

The compartment ID can be got from the Oracle web console, where we can click the profile icon in upper right and navigate to **Tenancy**. The OCID of the tenancy is what we need.

From the command above we can get the VCN ID, then we list all subnets in this VCN:

```
oci network subnet list --compartment-id <compartment id> --vcn-id <vcn id>
```

From the command output above we can find the ID for the subnet where our instances are running.

Also, we can get the security list for this VCN:

```
oci network security-list list --compartment-id <compartment id> --vcn-id <vcn id>
```

Now we have the subnet ID and all the IDs for the security list, we can use command to update the set of security list for the subnet. OCI CLI does not have the option to add or remove a security list for a subnet. We can achieve our goal by applying a diffrent set of security list each time.

Below is an example script for doing this:

```
#/bin/bash

#user choice:
mode=$1
if [ -z "$mode" ]; then
        echo "Usage: $0 <on|off>"
        exit 1
fi

if [ $mode != "on" ] && [ $mode != "off" ]; then
        echo "Usage: $0 <on|off>"
        exit 1
fi

#the subnet which has the two instances running:
SUBNET_ID="<subnet id>"

instances_public_access_security_list="<id 1>"
metrics_security_list="<id 2>"
default_security_list="<id 3>"

if [ $mode = "on" ]; then
        security_list="'[\"$default_security_list\", \"$metrics_security_list\", \"$instances_public_access_security_list\"]'"
else
        security_list="'[\"$default_security_list\", \"$metrics_security_list\"]'"
fi

cmd_str="oci network subnet update --force --subnet-id $SUBNET_ID --security-list-ids $security_list"
echo $cmd_str

eval $cmd_str
```

In this script I have three security lists. The IDs are copied from "oci network security-list list" output. *instances_public_access_security_list* is one to define all public access to the instances. So if user chooses running the script with 'on' option, we can use command 'oci network subnet update' to give a set of all three lists. If the option is 'off' we update the the set of the securiy list without *instances_public_access_security_list*.

By using this script we can simply turn on and off public access to the instances.
